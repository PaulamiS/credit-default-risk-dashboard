# Credit Default Risk Dashboard

Predicts which credit card customers are likely to default on their next payment, explains each prediction, and presents the results as an interactive dashboard that a collections or risk team could use to decide where to focus effort.

**Stack:** Python, XGBoost, SHAP, scikit-learn, Pandas, Streamlit, Plotly

## What it does

- **Cleans the data and engineers features:** credit utilization, payment-to-bill ratio, months delayed, maximum delay, delay and bill trends.
- **Trains an XGBoost classifier** with early stopping, evaluated with AUC-ROC and F1 on a held-out test set. The decision threshold is chosen on a validation split, not on the test set. A logistic regression baseline and 5-fold cross-validation are included for comparison.
- **Segments customers** into Low, Medium and High risk and shows how many actual defaults each segment captures.
- **Explains predictions with SHAP:** global risk drivers and a per-customer breakdown.
- **Audits for fairness:** SEX is excluded from the model inputs, then demographic parity difference and disparate impact ratio are checked by sex and age group.

## Dataset

"Default of Credit Card Clients" (30,000 customers, 6 months of payment history), from the UCI Machine Learning Repository and also available on Kaggle as `UCI_Credit_Card.csv`.

1. Download the file.
2. Put it at `data/UCI_Credit_Card.csv` (the UCI `.xls` file also works with `--data`).

The data comes from one issuer in Taiwan in 2005, so this project demonstrates the method and is not suitable for real lending decisions.

## Run it

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python train.py                  # trains the model, writes everything to outputs/
streamlit run app.py             # opens the dashboard
```

`python train.py --data path/to/file --out outputs` overrides the default paths.

## Project structure

```
train.py            data cleaning, features, XGBoost, SHAP, fairness audit
app.py              Streamlit dashboard
requirements.txt
data/               put the dataset here (not committed)
outputs/            generated by train.py (metrics, predictions, SHAP values, model)
```

## Dashboard tabs

1. **Risk overview:** customers and actual default rate by segment, probability distribution, and a business insight computed from the current filters.
2. **Risk drivers:** top features by mean absolute SHAP value, plus the SHAP summary plot.
3. **Customer explorer:** pick any customer and see the top factors that raised or lowered their risk.
4. **Model and fairness:** AUC-ROC, F1, precision, recall, cross-validation, baseline comparison, and the fairness audit.

## Results

After running `python train.py`, copy the contents of `outputs/results.md` here so the README shows your real numbers.

## Limitations

- Single-issuer, single-country, 2005 data.
- Fairness metrics are a screening tool, not proof of fairness.
- The model flags risk; it does not decide what action to take. A human process should sit on top of it.
